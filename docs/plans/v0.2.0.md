# LongCache v0.2.0 Implementation Plan — Safe Reuse

**Status:** implemented specification; local validation passed. See the [execution record](v0.2.0-execution.md) and [acceptance evidence](v0.2.0-acceptance.md) for completed work and external release gates. The baseline inventory and estimates below describe the original planning context.
**Prepared:** October 27, 2026.
**Baseline:** commit `8a47ebd`, the merged v0.1.1 implementation in the active `LongCache-fork/` checkout. The supplied planning document predates that checkout.
**Target:** v0.2.0, Python 3.11–3.12, one to two developers.
**Primary reference:** the supplied LongCache roadmap, milestone 0.2.
**Previous milestone:** [v0.1.1 changelog](../changelog.md).

## 1. Outcome and release limits

Version 0.2.0 makes cache eligibility explicit. A supported request can reuse an answer only when trusted scope, execution context, stored format, embedding generation, admission evidence, and verification policy all permit it. Similarity selects a candidate; it does not authorize reuse.

Version 0.1.1 is the completed implementation baseline. Preserve that work and its Python 3.10 compatibility. This plan builds on it in a separate v0.2 development line; baseline validation confirms the starting behavior. An independently discovered critical defect should receive a focused v0.1.x fix where appropriate.

The initial supported workload is non-streaming, single-turn text with explicit execution context. Memory, SQLite, and synchronous Redis storage remain single-process cache topologies. Async calls over these supported backends must follow the same decisions as sync calls. Standalone async Redis remains separate from the public cache orchestrator.

| Included in v0.2 | Kept in later milestones |
| ---------------- | ------------------------ |
| Canonical identity and trusted user/tenant scoping | Singleflight and broader failure recovery: 0.3 |
| Versioned persisted metadata and a safe upgrade path | Multi-instance consistency and distributed coordination: 0.4 |
| Explicit request-shape bypasses across every integration | Full conversations and validated streaming replay: 1.1 |
| Response admission and verifier hooks | Structured-output replay and telemetry exporters: optional 0.3 candidates |
| Explainable decisions, similarity scores, scoped inspection | External vector-store adapters: optional 1.4 candidate |
| Custom `BaseEmbedder` injection and compatibility validation | New embedding runtimes, providers, multimodal caching, and adaptive thresholds |
| Versioned evaluation dataset, runner, and published results | Negative caching and automatic retrieval-metadata discovery |
| Python 3.11 minimum and migration documentation | A stable 1.0 interface promise |

Response-format and schema options must be represented or bypassed in v0.2; supporting schema-aware identity does not promise structured-output replay. Explicit source-version identity is required now; automatic retrieval integration and distributed invalidation remain later work.

## 2. Historical v0.1.1 baseline inventory

This section preserves source-inspection findings from the v0.1.1 baseline before v0.2 implementation. It is not a description of the current v0.2 code. Current local results and external release gates are recorded in the [execution record](v0.2.0-execution.md).

Short source paths such as `core/cache.py`, `integrations/openai.py`, and `middleware.py` are relative to `src/longcache/`. Other repository paths are relative to the checkout root.

| Area | v0.1.1 baseline | v0.2 implication |
| ---- | ---------------------- | ----------------- |
| Context identity | `longcache/src/longcache/core/cache.py` hashes model, system prompt, and temperature into a shortened namespace suffix | Replace scattered context construction with one versioned identity module. |
| OpenAI requests | `integrations/openai.py` supports a conservative single-turn subset and scopes model/instructions/temperature | Retain the bypass discipline; add provider/deployment identity, trusted scope, versions, and explicit parameter states. |
| OpenAI responses | Dictionary responses permit a missing finish reason in some cases; SDK objects require `stop` | Use one strict admission contract with completion evidence and a defined response codec. |
| ASGI | `middleware.py` bypasses Authorization, Cookie, and X-API-Key requests; no trusted identity resolver exists | Keep these bypasses until trusted authentication context is available; never substitute a raw identity header. |
| Other integrations | LangChain and LlamaIndex can extract only part of an input and call the cache without model/instruction scope | Every entry point must use complete context or pass through without cache access. |
| Decorators and streams | Extra decorator arguments bypass; several stream helpers still cache and replay collected output | Preserve argument bypasses and explicitly disable unproven streaming cache paths. |
| Candidate selection | `core/index.py` returns an entry, hides the score, and normally increments its hit count | Return scored candidates without hit side effects; count only after verification and successful decoding. |
| Inspection | `core/cache.py` returns candidate query/instructions and metadata, but no similarity score or policy result | Add scope-aware, redacted decision inspection without changing hit counters. |
| Persistence | `core/entry.py` and built-in backends lack identity-format and embedding-generation metadata | Introduce an explicit v0.2 format; never promote under-scoped legacy entries. |
| Serialization | SQLite and Redis use `json.dumps(..., default=str)` for generic responses | Use strict, supported response codecs so a miss and a persisted hit have equivalent types. |
| Embeddings | `BaseEmbedder` exists; `LongCache` constructs `LocalEmbedder` directly; vectors lack persisted model/revision identity | Inject the embedder and validate both vector properties and generation compatibility. |
| Configuration | `CacheConfig.from_dict` silently drops unknown keys | Reject misspelled safety settings rather than accidentally accepting a weaker configuration. |
| Backend contract | Built-in backends implement `list_all_entries`, but the abstract contract does not declare it | Make enumeration and format requirements explicit for safe rebuilds. |
| CLI | Inspect/export/clear assume older namespace and storage semantics | Define scoped inspection and separate trusted operator access to owned cache data. |
| Runtime and CI | Metadata and Ruff target Python 3.10; CI covers 3.10, 3.11, and 3.12 | Move the v0.2 matrix and tooling to 3.11–3.12 and test 3.10 installation rejection. |

## 3. Required invariants

1. Tenant and user identity come from the trusted application or authenticated request context, never from model text or an unvalidated request field.
2. A namespace is a logical application grouping, not proof of identity or authorization.
3. Private requests without required identity neither read nor write the shared cache. A similarity search is not performed first.
4. Every response-affecting field is represented exactly or causes a documented bypass. Unknown fields are never silently discarded from identity.
5. The prompt text is the semantic search input. The remaining execution identity must match exactly before a candidate can be reused.
6. Lookup, storage, inspection, invalidation, and export selection use the same identity implementation. Future coalescing uses its exact-request key.
7. Legacy entries, unknown format versions, incompatible embeddings, invalid response payloads, and expired/deleted entries are never served.
8. Mandatory admission checks cannot be overridden by an application hook. Hooks may reject more entries, not approve unsupported ones.
9. Verification rejection, uncertainty, failure, or exhausted verification budget never becomes a hit.
10. Entry and global hit counts advance once per accepted, decoded cache result, not for inspection, candidate selection, or rejected replay.
11. Every supported sync path has an async decision-equivalence test. An async wrapper does not imply a fully async storage backend.
12. Raw payloads, instructions, credentials, identity values, and out-of-scope candidate details are absent from default diagnostics and response headers.

## 4. Proposed module design and interface

Use one deep policy module behind a small interface. Integration adapters translate provider/framework requests and responses; they do not implement their own identity hashes, tenant fallbacks, admission rules, or verification order. Keep these decisions local to the core so one fix applies to all callers.

Proposed new modules are implementation destinations, not files already present:

| Module | Responsibility | Interface constraint |
| ------ | -------------- | -------------------- |
| `core/identity.py` | Immutable scope/context values, canonical serialization, semantic partition and exact-request keys | Pure and deterministic; no provider or database dependency. |
| `core/policy.py` | Request eligibility, admission, verifier composition, stable decision codes | Inputs and explicit decisions; hooks cannot mutate identity. |
| `core/decision.py` | Typed lookup/store outcomes and redacted explanations | A small set of stable outcomes with optional same-scope scores. |
| `core/embedding_contract.py` | Embedding descriptor, vector validation, persisted compatibility checks | One validator for injected/local embedders and restart. |
| Existing `core/cache.py` | Orchestrate prepare, search, verify, decode, account, and store | Shared sync implementation logic with async execution of blocking work. |
| Existing `core/index.py` | Search scored candidates and maintain vector/index mappings | Candidate search has no hit side effects and never calls user hooks under its lock. |
| Existing integrations | Request adaptation, supported response codecs, trusted context resolution | Pass through anything that cannot satisfy the shared interface. |
| Existing backends | Store/retrieve versioned entries and store manifests | Preserve identity and codec metadata exactly; strict serialization. |

### 4.1 Public interface direction

The implementation should settle these names in the first delivery slice. The following is the recommended interface, not runnable functionality in v0.1.1:

```python
cache = LongCache(
    CacheConfig(backend="sqlite", scope_policy="private"),
    embedder=my_embedder,  # Optional; LocalEmbedder remains the default.
    admit=my_admission_hook,  # Optional; mandatory checks always run.
    verifier=my_verifier,  # Optional extension of the built-in policy.
)

context = RequestContext(
    scope=RequestScope(tenant_id="tenant-17", user_id="user-42"),
    operation="support.answer",
    provider="openai",
    provider_scope="production-deployment-a",
    model="configured-model",
    instructions=(Instruction(role="system", content="Approved support policy"),),
    generation={"temperature": 0.0},
    prompt_version="support-v3",
    corpus_version="knowledge-v8",
)

decision = cache.lookup("How do returns work?", context=context)
if decision.outcome == "HIT":
    answer = decision.response
else:
    answer = call_provider()
    stored = cache.set("How do returns work?", answer, context=context)
```

Export the new value types deliberately from `longcache/__init__.py`. Provide `alookup` and `aset` with identical outcomes. Preserve `get`/`aget` as convenience methods that return a response or `None` and delegate to the same policy. `lookup` is the authoritative interface for decision reasons. `set`/`aset` return a `StoreDecision`; document this change from the previous `None` return. Keep `None` responses inadmissible in v0.2 to preserve the convenience methods' miss semantics.

Retain legacy positional calling forms where they can be mapped unambiguously. Legacy model/prompt/temperature keywords must not override a supplied context: either map them when context is absent or raise a configuration error on conflicts. A call without sufficient context safely bypasses rather than falling back to v0.1 namespaces. Document the resulting cold-cache behavior as a v0.2 compatibility change.

Keep runtime hooks, scope resolvers, and embedders as constructor dependencies, outside serializable `CacheConfig`. Restrict configuration values from dictionaries/environment variables to supported scalar settings. Reject unknown keys and invalid policy values, with tests for misspellings.

### 4.2 Canonical identity

Separate three identities that have different jobs:

| Identity | Contents | Use |
| -------- | -------- | --- |
| Semantic partition | Canonical execution context plus policy, codec, format, and embedding identifiers; excludes current query text | Restrict semantic candidate reuse to compatible requests. |
| Exact request | Semantic partition plus the exact current query text | Identify identical calls; reserved for future singleflight, without implementing coalescing now. |
| Storage generation | Format version, installation/cache identifier, and one embedding fingerprint | Keep incompatible persisted vectors and legacy formats out of the active index. |

Required execution fields are logical namespace, sharing mode, trusted tenant/user scope, operation identifier, provider identifier, provider/deployment scope, model, ordered system/developer instructions, supported generation parameters, prompt version, and optional source versions. Include corpus/document version maps in a canonical order. Include the request-shape identifier, response-codec identifier/version, and explicit admission/verification policy version in the partition.

The operation identifier prevents two decorated functions or chains with the same query from sharing an answer accidentally. A function's short name, object `repr`, or memory address is not a sufficient stable operation identity. Provider scope identifies a configured endpoint/deployment, not an API key. A caller must declare a deployment/version token when a mutable model alias or hidden provider setting affects responses; document that LongCache cannot discover arbitrary upstream changes.

Canonicalization rules:

- Use a versioned, typed record and deterministic UTF-8 JSON with sorted mapping keys, compact separators, and rejection of NaN/infinity.
- Preserve instruction role, order, and exact text. Do not lowercase, trim, summarize, or Unicode-normalize instructions or query text to improve hit rate.
- Distinguish omitted, explicit `null`, and explicit parameter values. Replace the old `temperature=-1` identity sentinel internally; do not assume a provider default equals an explicit value.
- Accept a bounded set of JSON-compatible parameter types; reject unsupported objects, non-string mapping keys, ambiguous numbers, and duplicate JSON request keys. Do not use `str()` as an identity fallback.
- Use full SHA-256 digests over canonical bytes, with explicit version/type prefixes. Check persisted identity metadata as well as the digest when selecting entries. A digest is neither authentication nor encryption.
- Snapshot context once before lookup and reuse that snapshot for any resulting write. Mutating a caller's dictionary while the provider runs must not change the write partition.

For the first OpenAI slice, retain the current conservative parameter allowlist rather than adding every SDK option. Represent every accepted option and bypass others. `response_format`, structured schemas, tools, extra response choices, and untested sampling options remain bypassed until both their identity and replay contracts are implemented.

### 4.3 Trusted scope policy

| Policy | Identity requirement | Missing or invalid identity |
| ------ | -------------------- | --------------------------- |
| `private` — default | Nonempty trusted tenant and user identifiers | Bypass lookup/storage; optional strict configuration rejects missing resolver setup at startup. |
| `tenant_shared` — explicit opt-in | Trusted tenant plus an application declaration that answers may be shared within that tenant | Bypass when tenant is absent; never infer this mode from a missing user. |
| `public` — explicit opt-in | A named application/operation declared to produce public, non-personalized answers | Remain isolated from private/tenant partitions; bypass authenticated middleware requests unless an explicit trusted policy permits public sharing. |

A local single-user application can supply an explicit fixed private scope. There is no implicit `default` tenant. Raw `Authorization`, Cookie, X-API-Key, or user-supplied tenant headers must not become cache identity values. An ASGI scope resolver reads an authenticated principal installed by trusted middleware and produces an immutable `RequestScope`.

Resolve scope once per request and never store current identity on a shared wrapper instance. Concurrent requests from different users must not overwrite each other's context. Clearly document authentication middleware ordering. Resolver failure yields a cache bypass; it must not manufacture a shared scope.

### 4.4 Lookup, verification, replay, and accounting

```text
request → trusted scope → supported-shape check → canonical identity
        → embedding/store compatibility → scored same-partition candidates
        → current admission eligibility + verification → strict response decode
        → final expiry/deletion/context recheck → record one hit → return

missing identity / unsupported shape → bypass cache → invoke provider
no accepted candidate              → miss cache   → invoke provider
provider result                    → mandatory admission → application hook
                                   → strict encode → persist metadata/vector
```

Make candidate selection side-effect free. Add an internal scored-candidate iterator/result to `SimilarityIndex`; preserve the v0.1.1 eligible-neighbor behavior. If the closest eligible candidate fails verification, consider the next eligible candidate rather than stopping immediately. Deduplicate IDs across expanded searches, particularly with HNSW; do not assume approximate rankings remain stable when `k` changes.

Use a documented verification budget, initially eight candidates per request, so callback work is bounded. Exhaustion produces an explicit non-hit decision. Publish how often the budget prevents reuse and evaluate its impact on safe-paraphrase coverage. Approximate search may miss a useful candidate; it may not bypass scope or verification checks.

Run application hooks outside core/index/backend locks. Re-read candidate identity, presence, expiry, and codec validity before accepting a hit under the existing single-process mutation discipline. Concurrent deletion, sweep, or invalidation must not resurrect a previously selected entry. This is a replay correctness requirement, not a new distributed consistency promise.

Decode the documented response type before incrementing entry or global hit counters. A malformed SDK payload that forces a provider call is not a hit. For ASGI, a hit means an accepted decoded cache result selected for delivery; do not claim that the client received every byte. Inspection runs the same eligibility logic without hit/miss accounting, eviction, or writes.

### 4.5 Admission rules

Apply mandatory checks first, then the application admission hook. The same policy governs manual `set`, decorators, integration writes, and replay eligibility.

| Result class | Default decision |
| ------------ | ---------------- |
| Transport/provider exception, cancellation, non-success HTTP status | No cache write; preserve the original exception/status. |
| Incomplete output, truncation, missing required completion evidence | Reject storage. |
| Explicit refusal, tool call, unsupported modality or response shape | Reject storage. |
| Invalid JSON payload, unsupported object, codec failure, `None` | Reject storage; do not stringify into a superficially valid answer. |
| Supported complete response passing mandatory checks and optional hook | Store with identity, codec, policy, and embedding metadata. |

For OpenAI-shaped responses, require the documented complete text shape, nonempty choices, string content, and supported `finish_reason="stop"`. Reject missing/malformed choices and missing finish reasons rather than treating them as completed responses. SDK and dictionary paths must share equivalent checks. Preserve refusal/tool detection and reject non-finite/unserializable payload values.

For a generic string/JSON function, the library cannot infer all refusals or application errors from content alone. Document the supported primitive response subset and require an application admission hook for domain-specific validation. A callable returning normally establishes completion only for the supported non-generator function contract; it does not prove the answer is correct.

Require strict JSON encoding for generic responses and explicit versioned codecs for supported SDK objects. Do not use pickle or `default=str` to preserve unknown response types. Existing integrations with unproven response round-trips must bypass instead of storing opaque objects.

An admission hook receives the immutable request context and a normalized completed response view, then returns a typed accept/reject decision with a stable reason. Exceptions, invalid returns, and unsupported awaitables reject the write while preserving an otherwise successful provider response. Mandatory rejection cannot be reversed by the hook. Negative caching is disabled throughout v0.2.

### 4.6 Verification contract

Verification receives the current query, same-partition candidate query, normalized candidate response, score, and immutable context. It returns `accept`, `reject`, or `abstain`, plus a bounded reason code. `abstain` cannot approve a candidate. Application verification runs only after mandatory checks and can tighten the decision; it cannot approve cross-scope or unsupported data.

Implement small deterministic checks with versioned behavior:

- **Negation:** detect changes in supported English negation constructions and contraction forms. Test polarity and valid paraphrases; avoid claiming a complete linguistic equivalence check.
- **Numbers:** extract and compare numeric values with sign, units, currency, percentages, dates, and identifier distinctions where supported. Conservative parsing rejects ambiguous comparisons. Do not collapse `10%` and `10 dollars` to the same value.
- **Entities:** compare explicitly supplied protected entities and a documented conservative extractor for supported entity forms. Avoid a mandatory heavyweight NER dependency. Record extractor limitations and evaluate valid aliases and capitalization changes.

The built-in policy is enabled for the evaluated supported workload; an application hook is optional. Unknown language or unhandled ambiguity produces a reasoned non-hit rather than an assumption of equivalence. Passing these checks means no configured mismatch was detected, not proof that the two questions require the same answer. Include unprotected entity substitutions and relational changes in evaluation to expose this limit.

For this release, hooks are synchronous, local, and documented as bounded/pure functions. Async paths offload blocking work using the executor pattern; reject coroutine hooks during configuration instead of accidentally treating a coroutine as approval. A running Python callback cannot be forcibly cancelled. Cancellation observed before the hit-accounting or storage commit prevents that commit even if offloaded verification finishes later. A commit already in progress may complete; document this point of acceptance and test it explicitly. Remote model-based verifiers require a separately specified timeout/error contract and are deferred.

### 4.7 Decisions, inspection, and headers

Use `HIT`, `MISS`, and `BYPASS` as lookup outcomes and `STORED`/`REJECTED` as store outcomes. Attach a stable machine-readable reason rather than a free-form exception string.

Initial reasons should cover `accepted`, `no_candidate`, `below_threshold`, `missing_identity`, `invalid_identity`, `unsupported_request_shape`, `unsupported_parameter`, `legacy_format`, `embedding_incompatible`, `verification_rejected`, `verification_abstained`, `verification_budget_exhausted`, `hook_failed`, `response_inadmissible`, `codec_invalid`, and `expired_or_deleted`. Keep reason names centralized and tested.

Return a same-scope similarity score only when a compatible candidate exists. Inspection must not expose the presence, score, query, instructions, or response of an out-of-scope entry. Default inspection output contains outcome, reason, score, threshold, format/policy versions, and an opaque same-scope entry identifier. Payload inspection/export remains an explicit trusted operator action.

For supported ASGI responses, propose `X-LongCache: HIT|MISS|BYPASS`, `X-LongCache-Reason`, and `X-LongCache-Similarity` when applicable. Strip stale upstream copies of these headers. A post-response admission failure belongs in the local store decision; headers already sent must not claim a result that was unknown at response start. Unsupported streaming pass-through retains its upstream framing and avoids body buffering for diagnostics.

Remove existing debug logs that include raw query text or raw namespace values. The minimal decision output needed here is not an OpenTelemetry or Prometheus implementation.

## 5. Embedding interface and persisted compatibility

Extend the existing `BaseEmbedder` rather than introducing a parallel abstraction. Add a stable descriptor containing model identifier, immutable revision/version token, dimension, normalization contract, and preprocessing/version information. Resolve local model revision where possible; require an explicit operator version token when immutability cannot be established. A class name or vector dimension is not an adequate fingerprint.

Inject `BaseEmbedder` through `LongCache(..., embedder=...)`. A custom embedder takes precedence over the default local-model setting, and its descriptor is authoritative. Document that custom embedders do not remove the current required local-model packages in v0.2; lightweight packaging is later work.

Declare whether an injected embedder supports concurrent calls. Serialize calls per embedder when thread safety is not declared, including executor-based async calls; do not assume a custom model is thread-safe because the index is locked.

Validation requirements:

1. Dimension is a positive fixed integer and agrees with the descriptor.
2. Each single vector is a finite, nonzero, contiguous `float32` array of shape `(dimension,)`.
3. L2 norm is within a declared tolerance, initially `1e-3` of 1.0. Reject rather than silently normalizing an embedder that violates its declared contract.
4. Batch shape is `(count, dimension)` with equivalent row checks; an empty batch returns `(0, dimension)`.
5. Model/revision/preprocessing/normalization changes are incompatible even at the same dimension.
6. Validate before writes and validate persisted metadata before rebuilding FAISS. Never initialize an active index from an arbitrary first legacy vector.

A v0.2 storage generation has one embedding fingerprint. Reopening it with a different descriptor fails clearly before searching or appending vectors. Changing the embedder requires an explicitly new generation/path or an offline, separately reviewed re-embedding process; automatic re-embedding is outside this release. Validate corrupted individual entries without allowing them into the index, and report redacted counts/reasons.

Default local-model loading remains lazy where possible. A fresh empty store should not download weights merely for a metadata-only CLI operation. Resolve and validate the descriptor before the first vector operation or active-index rebuild. Include revision/configuration in `LocalEmbedder` instance-cache keys so singleton reuse cannot hide a model change.

## 6. Storage format, upgrade, and rollback

Choose a cold-cache upgrade as the supported initial migration. v0.1.1 records do not contain enough trusted identity to be promoted automatically. Preserving old answers is less important than preserving their correct scope.

### 6.1 Format requirements

Persist a store manifest with format version `2`, storage generation identifier, embedding descriptor/fingerprint, and codec metadata version. Each entry includes logical namespace, canonical execution-identity metadata/digest, format version, codec identifier/version, policy version, and existing TTL/tags. Store only the metadata required to validate scope; avoid additional raw identity copies when an opaque scoped token suffices.

Partition or index selection must be derived by the identity module, not by parsing user-supplied namespace suffixes. Treat backend access as trusted application access: opaque digests do not encrypt stored prompts or responses or protect against someone with database credentials.

For SQLite, use a new default path such as `.longcache/v2/cache.db` and a versioned schema/manifest. Opening a legacy file as a v0.2 active store fails with a clear migration message before modifying its contents. Do not implement an in-place rewrite or infer missing metadata. Make schema initialization transactional and detect partial/incompatible initialization.

For Redis, version the entire owned keyspace, for example `longcache:v2:<cache_id>:<generation>:...`, including entry keys, namespace/tag sets, ID counter, manifest, and statistics. Versioning only the entry namespace is insufficient. Match expiration semantics and never reset an entry's original expiry during a metadata operation. `clear` operates only on the explicitly owned v0.2 keyspace; never use `FLUSHDB` as a migration mechanism.

Make memory storage follow the same validation rules. Add required enumeration/manifest capabilities to the built-in backend contract, or an explicit capability check for custom backends. Unsupported custom backends fail clearly instead of silently dropping new metadata. Keep standalone async Redis accurately labeled; shared entry serialization changes require its own round-trip tests but do not add orchestration support.

### 6.2 Operator migration sequence

1. Record v0.1.1 settings and preserve its database or Redis prefix. Quiesce writes or use a consistent backup method; a raw copy of a live SQLite WAL database is not a sufficient backup procedure.
2. Install v0.2 on Python 3.11 or 3.12 in a separate environment.
3. Configure explicit sharing policy, trusted scope, operation/provider/model context, versions, and embedder descriptor.
4. Point v0.2 at a new SQLite file or its new Redis keyspace/generation. Run supported-example smoke tests with non-sensitive fixture data.
5. Expect misses until new complete responses pass admission. Confirm isolation and decision reasons before rollout.
6. Retain legacy data only under the operator's retention policy. Cleanup is explicit, scoped, and optional; no upgrade-time deletion is required.

Rollback stops v0.2 writers and restores the v0.1.1 environment and preserved store. v0.1.1 must not read the v0.2 store. Preserve the old Python/runtime environment if rollback requires Python 3.10. Tests must prove isolation between formats and that an interrupted v0.2 startup leaves the old store usable.

### 6.3 Scoped maintenance

`invalidate`, `invalidate_by_tag`, `inspect`, counts, and normal exports require the same trusted context or an explicitly privileged operator mode. Default invalidation targets the current semantic partition. Tenant-wide or all-partition maintenance is explicit and must not be reachable through an untrusted request's namespace/tag arguments.

Update CLI inspect/export to accept a context description or an explicit local operator mode and report the selected format/generation. Keep any destructive cleanup confirmation behavior. Do not silently make an existing `--namespace` command operate across every tenant. Document that cache scoping is a library contract, not a replacement for database or process access control.

## 7. Integration support matrix

Every advertised entry point must either satisfy the v0.2 contract or deliberately bypass. No integration retains a hidden v0.1 fallback.

| Entry point | Cacheable v0.2 subset | Required bypasses |
| ----------- | -------------------- | ----------------- |
| Manual sync/async cache methods | Supported string query, complete context, strict response codec | Missing identity/context, invalid vector, unsupported response type. |
| `@cached` | One query plus trusted per-call context resolver or fixed single-user context; explicit operation/version | Extra arguments not represented by a tested resolver; generators; mutable/unknown execution settings. |
| OpenAI wrapper | Existing supported single-turn text subset with complete context and tested dict/SDK replay | Multi-turn, tools, images/audio, streaming, unknown parameters, unsupported response format. |
| ASGI middleware | Supported route/shape, trusted identity resolution, explicit provider/deployment configuration, successful complete JSON response | Missing authentication context for private traffic, raw header-only identity, streaming, unsupported parameters, invalid/oversized capture. |
| LangChain `CachedLLM` | Only a tested adapter with explicit model/instructions/settings and stable response codec | Message histories, unrepresented kwargs/bound settings, unknown model state, unproven response type. |
| LangChain `CachedChain` / LangGraph examples | Explicit operation/context describing all generation/retrieval inputs; only tested replay types | Hidden memory, extra chain inputs, mutable graph state, missing source version for freshness-sensitive retrieval. |
| LlamaIndex `CachedQueryEngine` | Explicit generation context and caller-supplied corpus/version identity, with tested response codec | Opaque engine configuration, extra query options, unversioned mutable sources, unsupported response objects. |
| `cached_stream`, `StreamingCacheAdapter`, framework stream helpers | Pass-through only until identity and replay are proven | No cache reads or writes; expose/document `unsupported_request_shape`. |

For framework adapters that cannot meet the contract within the milestone, ship a documented bypass-only status rather than a partial implementation. At least the manual interface, decorator subset, OpenAI sync/async path, and supported ASGI path must be cache-capable for release; disabling all integrations is not an acceptable substitute for implementing safe reuse.

ASGI request handling must reject ambiguous duplicate-key JSON for caching while preserving upstream handling. Set a documented maximum cacheable request/response capture size. Large or streaming payloads pass through without unbounded cache buffering; do not truncate payloads and then cache them. Preserve upstream status/body and safe response semantics, and never replay another request's cookies or authentication-specific headers.

## 8. Evaluation specification and quality budgets

### 8.1 Versioned dataset and runner

The evaluation package is implemented at repository-root `evaluation/`. Run `uv run --no-sync python -m evaluation.run --config evaluation/configs/v0_2_release.json` from the checkout root. It runs the recorded protocol and writes JSON and Markdown results. See [evaluation and benchmarks](../benchmarks.md) for baseline preparation, the RAG workflow evaluation, and performance commands.

Dataset records include a stable case ID, group/split, seed cache entry, request/context mutations, expected reuse label, expected scope/shape decision, and source/freshness version. Use synthetic identities and license-compatible text. Document labeling rules; manually review ambiguous semantic labels instead of letting the cache judge its own correctness.

Split by semantic seed/family so a tuned paraphrase cannot leak into the held-out set through a near-identical variant. Keep the held-out labels out of tuning decisions. Record dataset hash/version, model revision, threshold, policy versions, random seed, FAISS settings, environment, and hardware. A changed dataset or policy needs a new evaluation record.

Initial held-out sizing targets:

| Group | Minimum cases | Purpose |
| ----- | ------------- | ------- |
| Safe paraphrases | 2,000 | Measure useful semantic reuse instead of only exact repeats. |
| Semantic near misses | 2,000 | Negation, quantities/units, entities, roles/relations, dates, and ambiguous wording. |
| Isolation/context changes | 500 | Tenant, user, model, provider/deployment, instructions, parameters, operation, and prompt versions. |
| Unsupported/missing identity | 200 | Conversations, tools, multimodal, streams, unknown parameters, and resolver failures. |
| Freshness/persistence cases | 100 | Corpus/document version changes, legacy formats, restart, deletion, expiry, and invalidation. |

Cases can be generated from a compact reviewed source dataset, but report the number of independent semantic families as well as expanded case counts. Correlated variants do not count as independent evidence of real-world error bounds.

Run v0.1.1 and v0.2 on the same supported public/synthetic workload with matched embedding model, threshold, cache population, and hardware. Evaluate private-isolation defects using fixtures, never real private traffic. Report scope improvements separately from common-workload reuse performance. Include both a fixed-threshold comparison and any development-set tuning protocol.

### 8.2 Metrics

| Metric | Required definition |
| ------ | ------------------- |
| Overall hit rate | Accepted hits / all requests, reported alongside exact-repeat and semantic-only results. |
| False-hit rate | Incorrect accepted hits / all accepted hits; undefined when there are no accepted hits. |
| Safe-paraphrase coverage | Correctly reused safe paraphrases / all labeled safe-paraphrase cases. |
| Bypass rate | Requests bypassing lookup / all requests, broken down by reason. |
| Verification rejection/abstention | Counts and rates among evaluated candidates; include rejection of safe paraphrases. |
| Admission rejection | Rejected writes / attempted writes, broken down by reason. |
| Latency | p50/p95/p99 for hits, misses, bypasses, verification, embedding, and index search; include cold start separately. |

Publish accepted-hit count and incorrect-hit count, not only percentages. Report a one-sided 95% binomial upper confidence bound for false hits with the method named, plus family-level results to disclose correlated samples. This describes the benchmark sample, not a universal correctness guarantee.

### 8.3 Initial acceptance budgets

These are proposed release targets established before tuning, not measured results. Freeze the budgets, workload, and hardware after the baseline slice and before threshold/policy tuning. Any later change requires a written scope/budget decision and a fresh evaluation version; do not relax targets after inspecting held-out failures.

| Gate | Initial target |
| ---- | -------------- |
| Deterministic scope and lifecycle acceptance suite | Zero cross-scope hits and zero served legacy/incompatible/expired/deleted entries. |
| Unsupported-shape and missing-identity suite | 100% bypass/no-store for the declared unsupported cases. |
| Semantic evaluation | False-hit point estimate at most 0.5%, one-sided 95% binomial upper bound at most 1%, and at least 1,000 accepted hits. |
| Useful reuse | At least 60% safe-paraphrase coverage on held-out supported English text; exact repeats reported separately. |
| Built-in verification overhead | p95 at most 5 ms for the declared bounded-query workload, measured without application hooks or embedding time. |
| End-to-end warm lookup overhead | p95 no greater than `1.2 × matched v0.1.1 p95 + 5 ms` on the frozen 1K/10K-entry workload; report HNSW separately from flat search. |
| Default diagnostics | No raw prompt/response/instruction/credential/identity values in snapshot checks. |

All gates apply together. If coverage or false-hit targets cannot be met, narrow and document the supported workload or improve the design and rerun a fresh held-out protocol. Bypassing every difficult request is not a passing evaluation. A supported workload with a known critical isolation defect cannot ship even if aggregate metrics pass.

## 12. Completion and release decision

The release is ready only when:

- Every included roadmap requirement maps to an implemented slice and acceptance evidence.
- Required manual, decorator, OpenAI sync/async, and ASGI cache paths pass; unsupported framework/stream paths bypass consistently and are accurately documented.
- Trusted identity and every represented context field remain isolated across lookup, storage, maintenance, inspection, and restart.
- Admission/verifier failures never authorize a response or store an invalid entry, and rejected replay does not inflate hits.
- Embedding/format incompatibility fails safely, legacy data remains untouched, and migration plus rollback instructions have been exercised.
- The frozen held-out quality, coverage, bypass, and latency gates all pass with published sample counts and limitations.
- Python 3.11/3.12, real Redis, clean wheels, SDK response round-trips, documented examples, and Python 3.10 rejection pass in the declared release matrix.
- Release notes identify interface changes, reduced cache reuse where appropriate, storage-format changes, supported workloads, and known verifier limitations.

Publish a v0.2 release candidate because identity and persistence semantics change. Reserve a documented feedback window before the final decision and rerun affected acceptance/evaluation checks after material fixes. If a gate fails, fix or narrow the supported feature with explicit evidence; do not mark the milestone complete solely because its target date or effort allowance has been reached.
