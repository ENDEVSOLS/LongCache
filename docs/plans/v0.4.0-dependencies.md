# v0.4 dependency investigation

**Decision:** defer a new embedding runtime and keep the existing NumPy `<2` constraint for this release. The current code accepts a caller-provided `BaseEmbedder`, so applications with a separately qualified runtime can use it without changing cache semantics. This decision does not claim that the default install is small.

## Measured current install

An isolated Python 3.11.16 environment installed the built development wheel with `longcache[redis]` after installing `torch==2.14.0+cpu` from the official PyTorch CPU index. The full environment occupied about 1.2 GB. Installed distribution file sizes, measured by summing `importlib.metadata.distribution(name).files`, were:

| Distribution | Installed files |
| --- | ---: |
| LongCache 0.3.0 development wheel | 0.3 MB |
| Torch 2.14.0+cpu | 682.2 MB |
| NumPy 1.26.4 | 61.7 MB |
| FAISS CPU 1.15.1 | 63.1 MB |
| sentence-transformers 6.2.0 | 2.5 MB, excluding its other dependencies |

Three fresh-process imports on that local host took 0.183–0.184 seconds for `longcache`, 1.251–1.272 seconds for `torch`, and 4.724–5.058 seconds for `sentence_transformers`. These are wall-clock startup observations with an OS cache that may already be warm, not portable cold-start guarantees. The default PyPI dependency resolution without preinstalling CPU Torch selected multi-gigabyte CUDA packages; that download was stopped. The isolated CPU wheel download was about 187 MB. The project should document CPU Torch installation before LongCache for CPU-only deployments.

To repeat the installed-file and import probe, create a clean environment, install CPU Torch followed by the built wheel, then run:

```python
from importlib.metadata import distribution
import subprocess
import sys
import time

for name, module in (
    ("longcache", "longcache"),
    ("torch", "torch"),
    ("sentence-transformers", "sentence_transformers"),
):
    files = distribution(name).files or ()
    size = sum(path.locate().stat().st_size for path in files if path.locate().is_file())
    started = time.perf_counter()
    subprocess.run([sys.executable, "-c", f"import {module}"], check=True)
    print(name, round(size / 1048576, 1), round(time.perf_counter() - started, 3))
```

## NumPy 2 experiment

In the temporary Python 3.11 wheel environment, NumPy was forced from 1.26.4 to 2.4.6 without dependency resolution, deliberately outside LongCache's declared `<2` range. The installed-wheel sync/async SQLite smoke and shared Redis write/read/invalidation/refill smoke both passed with FAISS CPU 1.15.1 and Torch 2.14.0+cpu. NumPy was then restored to 1.26.4. This small experiment does not cover the full supported FAISS range, model loading, or all integrations, so it is insufficient to widen the public NumPy constraint.

## Release choice

Moving Torch and sentence-transformers to an optional extra would substantially shrink installations that supply their own embedder, but it changes the default installation contract. An alternative embedding runtime also needs model-quality parity and compatibility evidence across Python, FAISS, and deployment modes. No such candidate passed those gates in this work, so v0.4 keeps the existing dependency contract. A later release can add an optional runtime after a pinned-model quality and clean-wheel matrix.
